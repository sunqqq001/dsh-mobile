# DSH Mobile（定制分支）

> 基于上游 [`saya-ch/dsh-mobile`](https://github.com/saya-ch/dsh-mobile) `v0.6.13` 的定制版本。
> 本分支只保留**一条自己的公网直连通路**，不再内置或分发任何第三方隧道。

在手机上安全、实时地使用电脑中的 DeepSeek Harness。插件不修改 DeepSeek Harness 源码。

## 与上游的区别

| 项目 | 上游 | 本定制分支 |
| --- | --- | --- |
| 远程通道 | Tailscale / cpolar / cloudflared / FRP / 自有反代 | **仅自有反向代理（公网 IP 直连）** |
| 通道选择界面 | 五个选项 | **只显示「自有反向代理」** |
| 第三方隧道组件 | 按需下载 | 已移除，不再下载 |
| Android App 下载 | 上游 Release | 本仓库 Release（`android-v0.6.14`） |
| 演示截图 | 随仓库分发 | 已移除（不随仓库分发图片） |

插件版本 `0.6.13`；配套 Android App `0.6.14`（versionCode 82）。

## 能做什么

- 在手机上继续电脑端的工作：同一份会话、工作区、消息和工具。
- 专属触屏布局：会话抽屉、工具详情、设置、提问卡片和输入栏按手机重新组织。
- 配对与多设备：扫码、链接或密钥配对一次；切换网络后通常自动恢复。
- 一键诊断：检查版本、网关、网卡、防火墙，生成脱敏报告。
- 任务系统通知：任务完成与待输入以 Android 系统通知提醒。
- 安全：局域网固定私有 CA；公网入口由插件内置反代终结 TLS；凭据存 Android Keystore。

## 工作方式

```
手机 ──> 公网 IP:3444（路由器端口映射）
           │  插件内置反代（改写 Host/Origin，保留 WebSocket upgrade）
           ▼
     电脑私网地址:3443（局域网网关，自签证书 + CA 钉扎）
           │
           ▼
       DSH Web（回环）
```

局域网直连走 `3443`；公网直连走 `3444`，由插件进程内的反代转发到局域网网关，不依赖任何第三方隧道。

## 快速开始

本仓库以本地 link 方式安装到 DSH profile（见[开发](#开发)），重启 DSH 后：

1. **移动访问 → 局域网** 开启并生成配对密钥，手机 App 扫码完成配对。
2. 需要在外部网络访问时，按[连接教程](#连接教程)配置公网直连。

## 连接教程

局域网与公网直连是两套独立的连接：在电脑附近优先用局域网（延迟最低），离开当前网络时再启用公网直连。电脑端分别管理开关与配对授权。

### 局域网访问

适合同一 Wi-Fi、以太网或手机热点，是默认且最简单的连接方式。

1. 打开 **移动访问 → 局域网**，点击 **开启局域网访问**。
2. 点击 **生成并复制密钥**，面板显示配对二维码。
3. Android App 选择 **局域网访问**，扫码或粘贴配对密钥。
4. 配对后建立持久设备信任，切换 Wi-Fi 或 DHCP 地址通常不需要重新配对。

端口说明：`dsh web --port` 修改 DSH Web 上游端口（默认 3080），插件自动跟随；`dsh-mobile setup --port` 修改 Mobile HTTPS 监听端口（默认 3443）。

### 公网直连

适合离开家庭网络后使用。前提是有**公网 IPv4**，并在路由器上把公网 `3444` 映射到电脑的 `3444`。

1. 在插件的 `mobile-access` 配置中设置：

   ```yaml
   publicEntry: https://<你的公网地址>:3444
   publicEntryAuto: true
   publicEntryPort: 3444
   ```

2. 重启 DSH。插件会探测当前公网 IPv4，并用 DSH 证书在 `0.0.0.0:3444` 启动内置反代。
3. 面板 **移动访问 → 远程**，点击 **生成远程配对二维码**。
4. Android App 选择 **远程访问**，扫码；证书提示选择继续（App 固定局域网 CA）。

公网地址变化时，插件在下次启动时重新探测；`publicEntryAuto` 关闭时使用配置里的静态值。CGNAT 环境下端口映射不可用。

## 扩展与自定义

在 DSH 对话里输入 `/mobile <需求>`，当前会话的 agent 会处理定制请求；文件修改完成后手机端通常会在几秒内刷新。

```text
/mobile 把手机端输入栏改成两行，并把发送按钮放到右侧
```

定制文件在 `$DSH_HOME/mobile-access/` 下：界面和交互在 `mobile.css` / `mobile.js`；需要电脑能力时用 `extensions/` 下的扩展，其 `host.mjs` 以本机用户权限运行。本分支的 `mobile.css` / `mobile.js` 保持为空实现。

定制需要从 **移动访问的配对入口**进入；直接打开普通 DSH 网页不等于完成移动配对。

## 可选模块与高级配置

移动页面模块设置（[模块说明](docs/CLIENT_MODULES.md)）可按设备选择加载哪些客户端插件，保存后下次手动打开生效。

**本分支不推荐 `excludedClientModules`**：排除插件会让移动端启动模块图不完整，界面回退成 DSH 标准前端（出现顶部标签栏、底部费用条）。需要排查某个插件造成的布局问题时，应直接在插件侧停用它，而不是从移动页面排除。

## App 与手机浏览器

| 方式 | 适合场景 | 说明 |
| --- | --- | --- |
| Android App | 日常使用 | 首次配对时分别提供局域网与远程入口；局域网自动发现；公网入口由 App 固定局域网 CA |
| 手机浏览器 | 临时或跨平台访问 | 打开「移动访问」卡片显示的 HTTPS 地址；局域网私有证书可能需要手动确认 |

Android App 只是 Kotlin WebView 薄壳，不内置另一份网页；手机浏览器访问的是同一页面。

## 设备管理

Android App 在「已配对设备」中显示电脑及其连接记录。局域网与远程授权彼此独立，同一台电脑可能有两行。

- 点按设备行连接；右侧「…」可重命名、立即检测、重新配对或删除本地记录。
- 启动行为可选「直接进入 DSH」或「显示设备列表」。
- 电脑端撤销会删除设备记录与令牌摘要；旧令牌之后一律 `401`。

## 第三方插件适配

- 网关默认只放行 DSH 第一方 WebSocket 路径（如 `/sidebar/ws/terminal`）。
- 社区插件的其他 WS 路径默认拦截，会在 **连接诊断 → 第三方 WebSocket 路径** 中列出。
- 只对确认过的精确路径点击 **允许**；不接受查询字符串或模糊前缀。

## 安全

- 局域网监听只用于可信网络；公网直连依赖路由器端口映射，请勿把网关端口直接暴露且不设配对。
- 未配对请求无法进入 DSH；不使用时建议关闭远程访问。
- 配对设备可以操作电脑上的 DSH，应视为完全受信任的设备；手机丢失请立即在电脑端撤销。
- 本定制分支不移除任何 DSH 原有的配对、CSRF 与设备校验。

## 故障排查

- **配对后反复 401**：旧 Cookie 残留。清除该站点的 Cookie 或重开 App，再重新扫码。
- **远程配对报 `pairing_tls_failed`**：检查 `publicEntry` 是否与手机实际访问的地址一致，且配对由局域网网关签发。
- **手机连上一会就断开、反复重连**：反代必须保留 `Connection: Upgrade` 与 `Upgrade: websocket`，检查中间代理是否过滤了这两个头。
- **升级后移动端界面回退成桌面版**：不要使用 `excludedClientModules` 排除插件，直接停用可疑插件。
- **换了路由器或 IP 后不可用**：先查端口映射，再查反代是否监听 `3444`。

## 兼容性

- 插件基线上游 `v0.6.13`；本分支仅在 Windows x64 + 自签局域网网关上验证。
- 公网直连要求公网 IPv4 与路由器端口映射；CGNAT 环境下不可用。
- Android App 与本仓库的插件配对；与上游官方 App 的签名不同，不能互相覆盖安装。

## 卸载

```powershell
dsh plugin --profile <profile> remove dsh-mobile
# 如需连同本机数据一起清理（不可恢复）：
dsh plugin --profile <profile> exec dsh-mobile purge --yes
```

卸载插件不会自动删除 `$DSH_HOME/mobile-access/` 中的证书、配对记录或自定义文件。
